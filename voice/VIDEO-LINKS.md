Video links run inside the authenticated owner's existing box. No broker, new network rules, credential mounts, cookies, login or DRM bypass. Discord stays calls-only. Enable VIDEO_LINK_ENABLED and VISION_ENABLED; STT uses only its explicit OPENAI_TRANSCRIBE_BASE_URL/API_KEY/MODEL with no fallback and zero retries.

The model gets five seconds and two sampled frames with captured interval audio. If that answers the user, STOP. Otherwise inspect_video_url accepts the returned opaque handle and next=true, an explicit start/end range, or up to two one-second timestamps. No automatic scan. Handles bind to the authenticated owner/request capability. Repeating a URL within that request reuses its ledger; failed attempts, overlaps, expired handles or fresh handle requests cannot reset the inspection budget. A new independent user request is a new inspection.

Defaults remain initial/chunk 5 seconds, initial 2 frames, cumulative unique coverage 20s, processed media 60s, 8 frames, actual decoded response bodies 32MiB, 25s download/decode/STT wall time and 8 attempts. Source position <=3600s, handle TTL 300s, 32 live handles and 16MiB cached artifacts. All have VIDEO_LINK_* env controls. Core reserves remaining limits for each helper call and permanently closes an inspection on unmeasurable failure. Body metering covers yt-dlp metadata plus all media HTTP response reads, not just advertised filesize. Reads never request beyond the remaining budget, fail closed when exhausted. This measures received/decompressed HTTP bodies, not TCP/TLS overhead. Per-file OS limits, CPU/deadline limits, streaming meter, ffmpeg/ffprobe output-file monitor and subprocess kill/wait protect the helper. Artifact directories are destroyed on success or failure. Existing owner box command deadline and sandbox resource/quota policy also apply.

Supported transfer paths, not site guarantees. Small muxed progressive formats are preferred, then small separate video/audio. MP4 uses bounded HTTP Range prefix requests with local ffprobe packet timestamps to stop once the requested interval is present. Front-indexed MP4 can avoid the rest of the file. Missing/end indexes, servers ignoring ranges or unindexed containers explicitly use whole-file-bandwidth-capped-fallback, through the SAME actual body budget. It is never labeled partial. Only the requested interval is input-seek decoded and sent to STT/vision, never the whole source. Seek/keyframe padding counts against the processed budget. Whole-file sources that exceed bandwidth/runtime caps fail rather than return fake success.

DASH uses extractor fragment timelines to fetch initialization plus only intersecting fragments. Unknown timelines may use the explicit whole-file fallback, still metered. Separate streams are locally remuxed; incompatible segment alignment fails safely. HLS supports selected MPEG-TS or unencrypted fMP4 initialization/segments, including separate video/audio. Encrypted HLS, unsupported byte-range/discontinuity semantics, DRM and live/upcoming/post-live sources are rejected. Mixed or unknown protocols may remain unsupported.

All network operations are Python/yt-dlp response reads in the existing owner box. ffmpeg/ffprobe only see generated local files/pipes and cannot use network protocols. Local format whitelist excludes playlist/concat demuxers and arbitrary embedded file references. Inputs are never shell commands. Generated artifact names, JPEG/WAV validation, byte/pixel/frame/sample caps and no-symlink/no-hardlink copy boundary remain. Source format/metadata, frames and transcripts are untrusted, not instructions or authorization.

Partial versus fallback mode and actual transferred body bytes appear in tool output. Cached coverage does not repeat downloads/STT. TTL cleanup runs on access and every 30s; expired artifacts are erased, while weak request ledgers deny same-request reset until that request is released.

Official docs read before implementation are https://github.com/yt-dlp/yt-dlp, https://ffmpeg.org/ffmpeg.html and https://ffmpeg.org/ffprobe.html. yt-dlp --download-sections requires ffmpeg; pinned FFmpegFD passes input -ss/-t and may use an external network downloader. We use the documented ffmpeg local-input seek and the allowed ranged-progressive/selected-fragment route instead, so external ffmpeg cannot bypass the byte meter. ffprobe -read_intervals selects packet ranges; actual seek points are not necessarily exact, so preroll is charged. Pinned yt-dlp 2026.8.19, m3u8 6.0.0 and existing distro ffmpeg.

Tests explicitly distinguish real versus mocked stages. A public YouTube Short was actually extracted/downloaded and decoded inside Yot's box into 2 frames and <=5s audio, without STT/vision provider requests. It selected HLS streams, NOT progressive MP4. MP4 and DASH tests use synthetic real media/real ffmpeg with mocked extractor/HTTP responses; they prove decoder and range/cap logic, not live-site MP4/DASH support. First unsupported-format attempts are retained in the private report, no endless retries or cookies. No universal YouTube/TikTok/Instagram claim.

URL first pass now returns publisher metadata plus four low-resolution, evenly spread storyboard previews. If no storyboard exists, it tries bounded ranged/segment seeks without whole-file fallback or audio extraction. Uploaded videos keep their existing five-second adaptive start.

Title, channel, description and chapters are publisher metadata, not visual proof. Available captions include source (manual or automatic), language, timestamps and truncation/coverage labels; they are not verified speech. No caption URLs are returned. Sparse preview timestamps are nominal storyboard positions or requested seeks, not exact decoded PTS or a full watch. Uncertain identities/actions need relevant bounded followups. User premises are not evidence.

Overview defaults are four frames, 320px, 8MiB and a one-hour source-duration limit. Metadata defaults are 4,000 description characters and 24 chapters. Captions share 64KiB/12,000 characters, one track and two attempted languages; manual tracks are preferred, automatic tracks are labeled and can be disabled with VIDEO_CAPTION_AUTO=false. See VIDEO_OVERVIEW_*, VIDEO_METADATA_* and VIDEO_CAPTION_* in .env.example. Every overview/followup spends the same owner-bound cumulative byte/frame/processed-time/wall/attempt/cache budgets. A failed attempt blocks reset, and expiry clears metadata/previews. No audio/STT runs for overview; targeted followups retain explicit provider isolation.

Scene previews use ffmpeg select/showinfo within a bounded local window, default 5s, with scene threshold 0.35 and periodic fallback. dHash dedupe uses 2 bits plus an RGB mean guard. Scan frame caps may stop decoding early; coverage notes and actual PTS say so. Initial URL results combine this window with whole-duration sparse storyboard or bounded seek previews. All processing/transfer/runtime/frame budgets remain cumulative.

search_transcript(handle,query) searches captured timestamped VTT/SRT cues or explicitly configured STT windows using literal/token matching. Stable segment IDs and provenance are returned, with unavailable distinct from no-match. It never calls an embedding service. get_frames(handle,start,end,n) uses the same inspection and budgets for scene-change sampling, adaptive periodic FPS and near-duplicate omission, without STT. Captions and metadata are untrusted; sparse previews never prove full viewing.
