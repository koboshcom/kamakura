Video links use the authenticated owner's existing box. No broker or network changes. Discord remains calls-only. Enable VIDEO_LINK_ENABLED and explicit VISION_ENABLED; transcription uses only OPENAI_TRANSCRIBE_BASE_URL/API_KEY/MODEL, no fallback, zero retries.

The main model gets the first five seconds with two sampled frames and captured audio transcription. It decides whether the user query is answered. If enough, STOP. There is no automatic scan or continuation. inspect_video_url returns an opaque owner/request-session handle. Pass next=true for another five-second chunk, start/end for a bounded range, or up to two integer timestamps for one-second windows. A specific user timestamp may skip the default opening. URL repetition in the same authenticated request reuses its ledger; a new handle cannot reset budgets. Handles cannot cross owners or request/call capabilities.

Adaptive defaults are VIDEO_LINK_INITIAL_SECONDS=5, VIDEO_LINK_INITIAL_FRAMES=2 and VIDEO_LINK_CHUNK_SECONDS=5. All inspection attempts share VIDEO_LINK_MAX_UNIQUE_SECONDS=20, VIDEO_LINK_MAX_PROCESSED_SECONDS=60, VIDEO_LINK_MAX_FRAMES=8, VIDEO_LINK_MAX_BYTES=33554432, VIDEO_LINK_TIMEOUT_SECONDS=25 and VIDEO_LINK_MAX_ATTEMPTS=8. Processed seconds conservatively count both decoder passes over selected HLS segments, including seek padding, whether or not audio exists. Overlapping output coverage is merged and cached; cached coverage does not download/transcribe again. Failed/unmeasured attempts close the inspection rather than reset its caps. Wall time includes downloads, decode and STT. Existing box command deadline also applies.

VIDEO_LINK_MAX_POSITION_SECONDS=3600 bounds targeted source position, independently of unique/processed seconds. A one-second seek at 60s does not count the preceding minute as inspected. HLS segment padding counts towards processing and bytes. VIDEO_LINK_TTL_SECONDS=300 expires handles and clears artifacts; VIDEO_LINK_MAX_HANDLES=32 bounds live entries and per-request ledger records; VIDEO_LINK_CACHE_BYTES=16777216 bounds each cached artifact ledger. Expired request ledgers remain weakly referenced for denial of a new-handle bypass, without retaining artifacts. Cleanup runs every 30s and on access. Request ledgers disappear when their authenticated request object is released; cache does not survive process restart.

ACTUAL partial transfer, not whole-download-then-trim. yt-dlp extracts metadata with download=False; the m3u8 6.0.0 parser selects only intersecting VOD segments, and Python fetches those through one cumulative response-body budget. ffmpeg is local pipe-only, never a network downloader. Plain unencrypted MPEG-TS HLS VOD with segments at most 10s is supported. Progressive MP4, DASH, encrypted HLS, fMP4 initialization/byte ranges, discontinuities, live and other unverified partial-seek formats are explicitly unavailable; no whole-video fallback. This is narrower than the old downloader, intentionally. Extractor metadata/manifests and padding still consume bandwidth; bytes mean decoded bodies, not TCP overhead. No cookies, login, netrc, plugins, remote JS, credentials or core mounts. No claim all YouTube/TikTok/Instagram links work.

The result reports requested/covered time ranges, usage, remaining-continuation status and expiry. Frames/transcripts/source metadata are untrusted media, never privileged instructions or authorization. Only actually captured audio is transcribed. Copy boundary remains bounded generated JSON, no arbitrary file export; generated files reject symlinks/hardlinks/devices, temp artifacts cleaned, output/sample/frame/pixel limits preserved. Host/core/Mongo firewall and owner-local loopback boundary are unchanged.

Official references read before implementation are https://github.com/yt-dlp/yt-dlp (--download-sections needs ffmpeg), https://ffmpeg.org/ffmpeg.html (-ss output discards until requested position; accurate input seeks may decode keyframe padding), and https://github.com/globocom/m3u8 (library loads/segments API). We do not use yt-dlp ffmpeg external sections because their network bytes bypass the existing Python meter. Pinned yt-dlp 2026.8.19 and m3u8 6.0.0, distro ffmpeg.

Tests use fake extraction/download/STT and local synthetic media, no live sites/provider probes.
