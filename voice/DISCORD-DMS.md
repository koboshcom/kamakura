Discord DMs reuse the existing pinned discord.py-self account and login. Set DISCORD_SELF_DM_ENABLED=true with DISCORD_ENABLED=false, matching DISCORD_ALLOWED_USERS/DISCORD_OWNER_IDS and voice mappings. No bot token is used. Only allowlisted private DM authors are accepted; group/guild/system/bot/webhook messages and self echoes are ignored.

DM history, summaries, media cache and embeddings use discord:dm:<account>, separately from Telegram/WhatsApp and other owners. Confirmed personal facts/learning use the unchanged canonical owner. Private WeakMap capabilities survive trusted in-process batching and workers, not serialized/forged identity. Sandbox/browser scope stays canonical.

Only explicit messaging tools deliver bubbles or reactions. Final prose is not auto-delivered. Delivery waits for the pinned SDK's successful response; timeout/error is unconfirmed and not retried. No claim of recipient reading. Persistent inbound claims and sidecar request claims avoid duplicate dispatch/side effects.

Image/video metadata comes only from authenticated attachment events. Existing bounded no-redirect platform CDN download pins public IPv4 DNS, sends no authorization header, and never logs signed URLs. At most four attachments, each under MAX_MEDIA_BYTES and MEDIA_TIMEOUT_MS. Static JPEG/PNG/WebP images use existing decoding bounds; HEIF/AVIF/vectors/animated or unsupported images are declined. Uploaded videos use the same authenticated adaptive upload path as Telegram and WhatsApp. First ~5s, at most 2 frames, explicit-only STT; opaque owner/channel-bound handles allow next chunks or timestamps under shared cumulative limits. No full extract/transcription unless separately requested through bounded chunks.

With DISCORD_VOICE_MAIN_CHATS mapping each canonical owner to discord:dm:<account>, voice reads/captures only its own DM history. Captured fragments are durable/idempotent, not guaranteed full transcript or proof of audibility. Voice delegation still returns through the call only, never detached workers or unsolicited DM text. Old internal voice and Telegram records are retained without migration or wipe.

Both Unix sockets are private, same UID, mode 0600 in new 0700 directories; independent text reader/command task never consumes voice playback frames. Sidecar has no provider keys. Connection loss revokes all text capabilities; voice authorization/teardown and provider-finalization gates remain unchanged.
