# Optional real macOS computer control

This is separate from Kamakura's sandbox desktop and disabled unless configured. It controls the logged-in user's primary display. GUI access can still open Terminal, send messages, delete files or buy things. No arbitrary shell/exec route is exposed, but that is not a substitute for reviewing each action. Screenshots leave the Mac and reach the bot/model provider. Close private windows first.

Install on the Mac, not in Docker. Use Python 3.11+ and a virtual environment, then `pip install -r host-agent/requirements.txt`. Grant the actual Python executable/terminal launching it Accessibility and Screen Recording in macOS System Settings > Privacy & Security. Restart the process after granting permissions. Run interactively in the logged-in desktop session. Moving the pointer into a screen corner preserves PyAutoGUI's emergency fail-safe. Stop the process to revoke access immediately.

Generate a different random secret per Mac/user using `python3 -c 'import secrets; print(secrets.token_hex(32))'`. Keep it outside source control and shell history. Set `HOST_AGENT_SECRET`, `HOST_AGENT_TELEGRAM_USER_ID` to the exact positive numeric Telegram sender ID, and `HOST_AGENT_BIND` to the Mac's operator-selected Tailscale IPv4 address (100.64.0.0/10). Then run `python3 host-agent/server.py`. It binds only that address on port 8765. No localhost, wildcard, public IP, DNS, HTTPS proxy, or arbitrary port is supported. The bind fails if that address is absent. Do not use port forwarding, Funnel, public reverse proxies, or expose this service outside the tailnet.

On the bot host, create a mode-0600 JSON file outside the repository containing an array such as `[{"telegramUserId":"123456789","endpoint":"http://100.64.10.20:8765","secret":"REPLACE_WITH_AT_LEAST_32_RANDOM_CHARACTERS"}]`. Set `HOST_COMPUTER_CONFIG_FILE` to its path. If Docker is used, mount only this file read-only and set the environment variable inside the core container. The bot host/container must have routing to the Mac's Tailscale address; the per-user sandbox tailnet alone does not provide core access. Each ID can have one host. Omit the variable to disable. Restart the bot to reload config or revoke a user.

HTTP runs over Tailscale's encrypted transport. Restrict Tailscale grants/ACLs to only the bot node identity reaching this Mac on TCP 8765, and deny all other tailnet callers. Remove existing broad allow-all policies; an additional narrow grant does not undo broad grants. Example grant shape is `{"src":["tag:kamakura-bot"],"dst":["tag:kamakura-mac"],"ip":["tcp:8765"]}` in your tailnet policy. Assign tags with restricted tag owners and test policy from both permitted and denied nodes. Also configure the Mac firewall to accept only the bot's Tailscale source IP on TCP 8765. Neither IP binding nor the secret replaces caller restrictions.

Input supports screenshot, click, move, printable ASCII typing up to 2000 characters, and up to four allowed key names. Coordinates are primary-display logical points, and screenshots are resized to those same coordinates. Unicode typing, clipboard changes, scrolling and arbitrary execution are not supported. Screenshots are capped at 4 MiB PNG; very large captures fail instead of sending an unbounded response. Requests are serial on the Mac, with five-second socket and eight-second action timeouts. Screenshots are temporary and deleted; request bodies, screenshots and secrets are never logged by the agent. UI state may change between approval and execution. Timeout does not mean an action did not happen; inspect before retrying.

## Bot integration contract

Import `HostComputers` and `hostInputSchema` from `src/host-computer.ts` and create one adapter for the process. Expose an opt-in tool only when `available(ctx.from.id.toString())` is true. The model may call `request(userId, input)` using the trusted sender ID, never an ID supplied in tool input. Screenshot requests run immediately. Every mutation only queues one user-scoped action for 60 seconds, returning a harmless summary and `confirm <nonce>` instruction. Typed contents are not echoed. A new mutation replaces the previous one.

In the authenticated Telegram text handler, before invoking the model, call `confirm(trustedSenderId, exactUnmodifiedText)`. Only an exact message consumes and executes the matching pending action. Do not expose `confirm` as an AI tool, strip/normalize input into a match, or accept model-generated confirmation. Require a private chat for all host operations and confirmations; never trigger them from forwarded messages, bots, group messages, attachments or extracted document text. Return `text` to the user and send each `images` PNG-base64 item as a photo/document. Do not log tool arguments, HTTP headers, images, config contents or full errors. Safe generic errors are returned. Authentication sends Bearer credentials plus `X-Telegram-User-Id`; the server checks both with constant-time comparisons.

Mocked TypeScript tests cover endpoint restrictions, owner isolation, replacement, replay, exact messages, expiry and response limits. Python validation/HTTP tests run without a Mac. Actual Accessibility, screenshot coordinates, permissions, firewall policy and input execution still require a live macOS smoke test. Official usage reference consulted at https://pyautogui.readthedocs.io/en/latest/quickstart.html .
