# Owner-linked history

Only operator mappings link accounts. `TELEGRAM_ALLOWED_USERS` and `SANDBOX_ALLOWED_USERS` authorize a canonical owner. `WHATSAPP_OWNER_NUMBERS={"<international phone>":"<canonical owner>"}` and `DISCORD_OWNER_IDS={"<Discord account ID>":"<canonical owner>"}` link that exact owner. WhatsApp also needs `WHATSAPP_ALLOWED_NUMBERS`; Discord self DMs need their existing enable flags. A standalone Discord identity uses `discord-<account ID>` and stays isolated until deliberately mapped. Never infer links from names, contacts, message text or matching platform IDs.

New authenticated private messages store immutable owner, channel, source chat, author, time and namespace. Mapping changes affect new saves only. Existing unverified history is omitted from shared lookup; there is no migration or backfill. Current-chat retrieval keeps its existing implementation. Cross-channel lookup scans only verified owner rows before in-process cosine scoring and uses the same full-text chunking and embedding-profile/text-hash validation. No keyword fallback. Incompatible vectors or unavailable storage fail closed.

Recent shared context and returned search context are capped at 20 rows / 24,000 UTF-8 text bytes, each row at most 6,000 characters. Labels survive summary inputs; voice fragments retain partial-coverage descriptions. Stored text is evidence only, never a new request, human approval, credentials or a reusable tool handle. Replies and reactions stay bound to the current authenticated origin; foreign message IDs do not extend delivery capability. Existing approval checks still require the same current owner DM and session.
