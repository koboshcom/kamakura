Sandbox boundary deployment notes

These changes are source-only until an operator schedules migration. Do not restart the core against the existing ext4 daemon and expect writable boxes to work. Writable remapped root now requires classic overlay2 backed by XFS with project quotas. Docker validates the project-quota mount when creating a container with StorageOpt.size. Containerd image-store drivers are rejected because accepting a size option is not proof of enforcement.

SANDBOX_ROOTFS_MODE defaults to writable when SANDBOX_USERNS_ROOT is enabled, retaining sudo and apt. SANDBOX_ROOTFS_SIZE defaults to 8G per writable image layer. SANDBOX_ROOTFS_MODE=readonly is the explicit optional fail-closed mode, not the remapped default. Non-remapped sandboxes remain read-only. Rootfs installs disappear when the container is removed; /work remains the only persistent user mount and retains its separate 35GiB filesystem quota.

Prepare a dedicated, preallocated, fixed-capacity XFS filesystem for the remapped daemon data-root, mounted with pquota/prjquota and formatted with ftype=1. Its aggregate fixed capacity protects the host even if metadata, images or logs grow. Do not place an unbounded sparse image on the production root filesystem. Preserve the old daemon directory for rollback. Stop the remapped daemon before copying or changing its storage. Select classic overlay2 explicitly and disable the containerd snapshotter. Do not change the primary daemon. Load the existing sandbox image into the new daemon, verify userns-remap is still enabled, and verify its info reports overlay2 and XFS. The provisioning/migration procedure must be supplied and separately approved before deployment.

Before trusting writable quotas, use a disposable small layer to write beyond its configured limit and confirm ENOSPC, without filling production storage. Verify sudo apt installation under the intended 8G limit and disappearance after deleting the disposable box. Neither test has been run by this patch.

Run deploy/remapped-network.sh as root after core recreation and before allowing sandbox calls. It delegates to the Python policy installer. Set SANDBOX_ROOT to the real root-owned workspace parent, SANDBOX_INSTANCE to the same value as core, and DOCKER_SOCKET_PATH to the dedicated daemon socket. KAMAKURA_CORE_CONTAINER and KAMAKURA_CORE_NETWORK select the primary core explicitly. SANDBOX_NETWORK_NAME, SANDBOX_NETWORK_BRIDGE, SANDBOX_NETWORK_SUBNET and SANDBOX_EGRESS_INTERFACE are configurable. Name and bridge must also match core environment. The default dedicated subnet is 172.30.0.0/24; avoid overlap with existing LAN/VPN/daemon networks.

The script creates only a dedicated labeled bridge and its own firewall chains. It rejects an existing network with a different policy. IPv4 sandbox ingress to host INPUT is denied; new egress to private, link-local, CGNAT, multicast and other reserved destinations is denied before permitting public egress over the selected WAN interface. Same-bridge and other non-WAN egress is denied. Core may initiate TCP6080; sandbox replies to that core flow are allowed, not new connections to core. WAN replies require established conntrack state. IPv6 bridge INPUT and FORWARD are dropped. The script writes a root-owned policy marker tied to boot ID, network ID, subnet and current core IP only after all commands succeed. Missing or stale markers prevent new sandbox calls. Partial firewall install retains a guard and never writes a success marker. An operator who changes firewall rules later must invalidate the marker and rerun the installer; the marker attests hook execution, not continuous independent firewall verification.

After applying in a maintenance window, explicitly test public HTTPS and DNS, denied host gateway/private LAN/metadata/CGNAT destinations, denied owner-to-owner access, denied IPv6, and authorized core desktop HTTP plus RFB. Recreate core once and confirm stale-marker rejection followed by recovery only after rerunning the hook. Confirm reboot startup orders storage mount, daemon startup, core startup and policy hook. No live firewall or deployment checks have been performed by this patch.
