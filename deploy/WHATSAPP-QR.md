# Isolated QR transport, integration review required

This branch adds Baileys 7.0.0-rc14 (MIT, WhiskeySockets/Baileys, approximately 11k GitHub stars checked during implementation). It is not integrated into index.ts, not deployed, not pushed, and requires no Meta business account or HTTPS webhook. WhatsApp Web automation can cause bans and protocol breakage. Use an alternate number only with informed operator approval.

## Configuration

Disabled by default. WHATSAPP_ENABLED=false requires no auth or mapping. Enabling requires WHATSAPP_AUTH_DIR pointing to an absolute dedicated private secret volume outside repository, data and sandbox roots. Do not mount that volume, its ancestors, or core filesystem into owner sandboxes. Directory mode must be 0700 and owned by the runtime UID; state file is 0600. Deployment isolation is a mandatory operator responsibility, not established by a path check alone.

WHATSAPP_OWNER_NUMBERS is JSON mapping actual E164 numbers (including +) to canonical IDs 6612253937 or 7853500388. Do not guess their numbers. For example, an operator-supplied number maps to its verified canonical owner, not a contact name. WHATSAPP_ALLOWED_NUMBERS is a comma-separated list of those exact E164 numbers. SANDBOX_ALLOWED_USERS must also explicitly include each canonical owner. No wildcard in either authorization list. MAX_MEDIA_BYTES is honored up to 20 MiB.

Run npm run build then node dist/whatsapp-pair.js in a local interactive terminal with the configuration set. The QR grants account access. Never screenshot, retain, forward, or print it in centralized logs. Runtime start does not print QR or create new auth. Repair is explicit: stop runtime and rerun pairing locally. Logged-out sessions are not deleted automatically. A crashed process leaves process.lock; verify no process uses the volume before manually removing that lock. Never delete credentials automatically. Keep encrypted operator backups separately if needed.

## Architecture and restrictions

Authentication uses official BufferJSON and AppStateSyncKeyData conversion with a single serialized, fsynced atomic snapshot containing credentials and signal keys. Baileys useMultiFileAuthState source warns against production use; it is deliberately not used here. Authentication corruption fails closed. Runtime library logs are silent. Auth snapshots never enter Mongo/history. Mongo stores unique hashed inbound claims only, with namespace derived from session path. Claims have no TTL to preserve restart deduplication. Claim-before-delivery is at-most-once, not guaranteed delivery: a crash after claiming can drop a message, intentionally avoiding duplicated privileged actions. Mongo failure drops processing rather than delivering unclaimed messages. A bounded queue of 32 pending items drops overflow.

Only private owner DMs are delivered. Group, status/broadcast, own echoes and unresolved LIDs are ignored. LIDs resolve solely through trusted upstream WhatsApp envelope mapping exposed through Baileys (not independent cryptographic PN ownership proof), never message-supplied phone hints. notify events only, age <=120 seconds, no history append handling. Forwards, quote context and media are never credential/learning eligible. Quoted context is bounded/redacted and carries no sender authority. Own-message reactions require an accepted inbound key retained in bounded process memory. No self-chat mode.

Inbound media is explicitly disabled. No encrypted download helper, remote fetch, media decoding, or temporary file creation is performed. Owner media messages carry an unavailable-inspection notice and are not learning/credential eligible. Earlier fake-stream cancellation tests did not establish actual rc14 cancellation and are not production evidence. View-once/ephemeral wrappers, documents, edits and other message types are deferred. Outbound text is plain WhatsApp text in sequential chunks capped at 16k; Markdown translation is deferred. Outbound quoted replies use accepted inbound message keys and a redacted 2k text-only cache bounded to 256 entries with five-minute expiry. Missing or expired targets fail closed. Outbound voice implementation is unchanged and provisional, not live-audited: it uses PTT only for Ogg containing OpusHead; otherwise a generic audio file attachment. Do not enable the voice capability at integration until codec/container handling and live delivery are audited. No transcoding or outbound image/video API yet. Typing emits one composing/paused pair per turn, no polling.

Reconnect has capped exponential delay and eight attempts; logged-out/bad-session stops with credentials preserved. Pairing restart-required is capped separately. Outbound failures are never retried because delivery may be uncertain.

## Parent integration gates

Add the transport only when explicitly enabled and pass authenticated canonical senderId into owner routing. Existing workTools/canWork, learning.ownerEvidence, local-device tools and reminder authorization are Telegram-only. They intentionally remain unchanged here, so WhatsApp sandbox/local-device access, learning and reminders remain unavailable until separately audited integration. No calls, GPT realtime, Cloud API, telephony or MeowCaller implemented. OpenClaw native requester-only call notification is not a realtime telephony bridge.

Check/build and fake-based transport/auth tests pass. Tests cover authorization ordering, unresolved LIDs, groups/fromMe, stale timestamps, forwarding eligibility, duplicate claims, simulated Mongo outage, private file modes, buffers/app state across restart, process locking, symlinks, oversized media and uncertain outbound behavior. Real WhatsApp pairing/delivery, live LID migration, actual media streams, reconnect lifecycle and sandbox mount isolation are not validated. They require operator-controlled integration testing before enabling in production.

Independent review read in full. Media deferred because rc14 drops AbortSignal before headers and does not prove upstream cancellation or integrity. No dependency patch/custom crypto attempted. Auth persistence failure emits the fixed auth-persistence-failed operator callback, stops the transport, poisons further access intentionally and requires restart from the durable snapshot. Injected write/fsync/rename key-store tests cover fail-closed/restart. Ancestors require root/current UID ownership and no group/world write except the exact root-owned sticky /tmp directory, with an immutable root; actual volume mount isolation remains an operator integration gate. Thirteen focused test groups and check/build pass. Shared chat-tool ID schemas and owner/tool integration remain untouched and blocking integration.

Final residual-review followup adds pairing factory/restart/end cleanup fakes, current-socket checks across pending LID resolution and durable claims, uncommitted snapshot cleanup, voice quote/cross-chat/cache-bound tests and foreign-UID ancestor test when root permissions permit. Pairing helper is import-safe and injectable for non-live testing; only direct CLI execution starts interactive pairing. No live pairing or integration approval.
